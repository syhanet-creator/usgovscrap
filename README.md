# 미국 중앙부처 보도자료 모자이크 (자동 한글 번역)

미국 연방정부 17개 기관(백악관 + 15개 주요 부처 + EPA)의 공식 사이트에서 최근 7일
보도자료를 수집하고, 제목을 한글로 자동 번역하여 모자이크 타일 형태로 보여주는
로컬 웹앱입니다.

한국 중앙 부처용 앱(`govscrap` 폴더)과는 별개의 독립 프로젝트입니다.

## 구성 파일
- `scrape.py` — 각 기관 공식 사이트(RSS 또는 목록 페이지)에서 보도자료를 수집하고
  한글로 번역해 `data.json`으로 저장
- `index.html` — `data.json`을 모자이크(masonry) 타일로 보여주는 화면
  (기관/제목 검색, 기관별 필터 지원)
- `serve.py` — 로컬 웹서버를 띄워 `index.html`을 `http://localhost`로 열어줌
- `run_all.py` — 패키지 설치 → 스크랩+번역 실행 → 웹서버 시작을 순서대로 수행
  (run.bat/run.sh가 호출)
- `run.bat` — 윈도우용 실행 스크립트 (더블클릭)
- `run.sh` — macOS/Linux용 실행 스크립트

## 처음 사용하는 방법

### 윈도우
1. `run.bat` 파일을 더블클릭
2. Python이 없다면 먼저 https://www.python.org/downloads/ 에서 설치 (설치 시 "Add to PATH" 체크)
3. 자동으로 패키지 설치 → 스크랩+번역 실행 → 로컬 서버 시작 → 브라우저에서 결과 페이지가 열립니다
4. 콘솔 창(검은 창)은 닫지 말고 그대로 두세요. 이 창이 곧 서버이며, 닫으면 웹앱도 함께 꺼집니다.

### macOS / Linux
```bash
cd govscrap-us
./run.sh
```

## 이후 최신 데이터로 갱신하려면
`run.bat`(윈도우) 또는 `./run.sh`(macOS/Linux)를 다시 실행하면 됩니다.
(`index.html`의 "새로고침" 버튼은 화면만 다시 그리는 것이고, 실제로 최신 자료를
다시 긁어오려면 스크립트를 다시 실행해야 합니다.)

## 왜 `index.html`을 더블클릭해서 바로 열면 안 되나요?
`index.html`을 파일 탐색기에서 더블클릭해 `file://` 경로로 열면, 최신 Chrome/Edge
브라우저는 보안 정책상 같은 폴더의 `data.json`을 `fetch()`로 읽는 것을 차단합니다.
이를 피하기 위해 `run.bat`/`run.sh`가 `serve.py`로 작은 로컬 웹서버
(`http://127.0.0.1:8765`)를 띄운 뒤 그 주소로 브라우저를 엽니다.

## 수집 대상 기관 (17곳)
백악관 · 국무부 · 재무부 · 국방부(War Dept.) · 법무부 · 내무부 · 농무부 · 상무부 ·
노동부 · 보건복지부 · 주택도시개발부 · 교통부 · 에너지부 · 교육부 · 국토안보부 ·
보훈부 · 환경보호청(EPA)

## 동작 원리
- 기관마다 사이트 구조가 전혀 달라, 다음 순서로 최대한 자동 대응합니다.
  1. RSS 피드가 있는 기관(백악관 계열, 국방부, 법무부, 보건복지부 등)은 RSS를 우선 사용
  2. 없으면 목록 페이지에서 `<time datetime>` 태그 또는 "09/18/2026"·"September 18, 2026"
     같은 날짜 텍스트를 실마리로 삼아 그 근처의 제목 링크를 찾는 범용 전략을 사용
  3. 그래도 못 찾으면 기사처럼 보이는 링크만 최후 수단으로 수집
  4. 날짜를 알아낸 항목은 최근 7일 이내인 것만 남기고, 날짜를 전혀 알 수 없으면
     목록 순서(최신순 가정)로 상위 몇 건만 사용합니다.
- 번역은 구글 번역(무료, 비공식 엔드포인트)을 우선 시도하고, 요청이 막히면
  MyMemory 번역으로 자동 전환합니다. 두 방법 다 실패한 항목만 원문 그대로 표시됩니다.
  두 서비스 모두 API 키가 필요 없는 무료 서비스이며, 품질은 유료 번역기보다는
  떨어질 수 있습니다 — 정확한 내용은 타일을 클릭해 원문에서 확인하세요.
- EPA는 접속 시 자동 차단(봇 감지)이 걸려 있어, 개별 항목 대신 보도자료 페이지
  링크만 제공합니다.

## 문제 해결
- **일부 기관이 항상 "목록 페이지 링크만" 뜨는 경우**: 해당 기관 사이트가 클라우드/
  서버성 IP를 차단하는 경우가 많습니다(Akamai 등 WAF). **회사·학교 네트워크가 아닌
  일반 가정용 인터넷의 개인 PC**에서 실행하면 대부분 정상적으로 수집됩니다. 그래도
  안 되면 사이트 구조가 바뀐 것이니 `scrape.py`의 해당 기관 `strategy`를 점검하세요.
- **번역이 영어 그대로 나오는 경우**: 번역 서비스 두 곳(구글/MyMemory)이 모두 일시적으로
  막힌 상태입니다. 시간을 두고 다시 실행해 보세요.
- **일부 기관의 보도자료 수가 유난히 적거나 0건인 경우**: 실제로 해당 기관이 최근
  7일간 보도자료를 내지 않았거나, 목록 페이지에 날짜 정보가 부족해 안전하게 걸러낸
  것일 수 있습니다. 상단의 "기관 보도자료 페이지 바로가기" 링크로 원본을 확인하세요.

## 매일 자동 갱신 (GitHub Actions + Vercel)
- `.github/workflows/daily-update.yml`이 매일 06:00(KST)에 `scrape.py`를 실행해 `data.json`을 갱신·커밋하고,
  그 푸시를 Vercel이 감지해 자동으로 다시 배포합니다. 수동 실행은 GitHub의 Actions 탭에서 "Run workflow".
- 번역은 `GEMINI_API_KEY`가 있으면 Gemini를 우선 사용합니다(없으면 구글 번역/MyMemory로 대체).
  **Vercel에 등록한 키는 GitHub Actions에서 읽을 수 없으므로**, 저장소 Settings → Secrets and variables →
  Actions에 `GEMINI_API_KEY`를 별도로 등록해야 합니다.
- 수집 항목이 10건 미만이거나 번역이 절반 이상 실패하면 기존 `data.json`을 덮어쓰지 않고 실패 처리합니다.
